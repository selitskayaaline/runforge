# RunForge

RunForge — frontend-приложение для просмотра запусков и анализа результатов их выполнения. Интерфейс позволяет находить нужные запуски, отслеживать их статусы и просматривать подробности каждого запуска.

## Функциональность

- **Список запусков.** На главной странице отображаются запуски с основной информацией: названием, репозиторием, статусом и продолжительностью выполнения.
- **Поиск.** Поиск помогает быстро найти запуск по названию или репозиторию.
- **Фильтрация по статусу.** Список можно отфильтровать, чтобы отдельно просматривать успешные, неуспешные и выполняющиеся запуски.
- **Сортировка.** Результаты можно упорядочить по доступным параметрам, чтобы быстрее находить нужные записи.
- **Подробности запуска.** При выборе записи открывается боковая панель с дополнительной информацией о запуске, включая сведения о выполнении, логи и результат.
- **Состояние интерфейса в URL.** Поисковый запрос, выбранный фильтр, сортировка и идентификатор открытого запуска синхронизируются с query-параметрами. Ссылку на конкретное состояние страницы можно скопировать и открыть отдельно.
- **Навигация по истории браузера.** При переходе назад или вперёд приложение восстанавливает состояние фильтров и выбранного запуска в соответствии с URL.
- **Состояния загрузки и ошибок.** Во время получения данных отображается skeleton. Если загрузка завершается ошибкой, пользователь видит сообщение и может повторить запрос.
- **Пустой результат.** Если по текущему поисковому запросу и фильтрам ничего не найдено, отображается отдельное empty state с возможностью сбросить условия поиска.

## Архитектура

Код разделён по функциональным областям. Компоненты, сервисы, хуки и вспомогательная логика функциональности запусков находятся в `features/runs`, общие элементы интерфейса — в `layout`.

```text
src/
├── app/                  # Application initialization
├── features/
│   └── runs/
│       ├── components/   # Runs feature components
│       ├── data/         # Mock data
│       ├── hooks/        # Custom React hooks
│       ├── services/     # Data access
│       ├── types/        # TypeScript types
│       └── utils/        # Filtering and formatting utilities
├── layout/               # Shared application layout
└── ...
```

## Запуск

Требуется Node.js и npm.

Установить зависимости:

```bash
npm install
```

Запустить приложение в режиме разработки:

```bash
npm run dev
```

Собрать production-версию:

```bash
npm run build
```

Запустить тесты:

```bash
npx vitest run
```

## Тестирование

Тесты проверяют основные части приложения и пользовательские сценарии:

- фильтрацию и сортировку списка запусков;
- форматирование дат и продолжительности;
- получение данных сервисом, обработку ошибок и повторную загрузку;
- отображение статусов;
- загрузку списка, поиск и комбинирование фильтров;
- открытие и закрытие панели подробностей;
- синхронизацию состояния страницы с URL и историей браузера.

## Демонстрация ошибки загрузки

Для проверки error state откройте приложение с query-параметром `demoError=1`:

```text
YOUR_DEPLOYED_URL/?demoError=1
```

В этом режиме сервис возвращает ошибку загрузки, а интерфейс отображает состояние ошибки. Нажмите **Retry**, чтобы повторить запрос и проверить восстановление списка.

## Ограничения

В текущей версии используются демонстрационные данные. Получение данных реализовано через отдельный service layer с имитацией задержки загрузки.

Приложение демонстрирует frontend-интерфейс и обработку состояний, но не подключено к реальному backend. Запуски не выполняются фактически, а отображаемые сведения и логи являются демонстрационными.
