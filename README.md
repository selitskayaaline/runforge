# RunForge

RunForge — frontend-приложение для просмотра запусков и анализа результатов их выполнения. Интерфейс позволяет искать запуски, отслеживать их статусы, сортировать список и просматривать подробности выполнения.

## Демо

**Live Demo:** <https://runforge-henna.vercel.app/>

## Функциональность

- **Список запусков.** Отображение демонстрационных запусков с названием, репозиторием, веткой, статусом, датой создания и продолжительностью.
- **Поиск.** Поиск по названию запуска или имени репозитория без учёта регистра.
- **Фильтрация по статусу.** Фильтры `Queued`, `Running`, `Succeeded` и `Failed`, а также просмотр всех запусков.
- **Сортировка.** Сортировка по дате создания — от новых к старым и наоборот; по продолжительности — от коротких запусков к длинным и наоборот. Запуски без указанной продолжительности располагаются в конце.
- **Подробности запуска.** При выборе запуска открывается боковая панель с репозиторием, веткой, датой создания, продолжительностью, логами и результатом, если он есть.
- **Управление боковой панелью.** Панель закрывается кнопкой, нажатием на фон или клавишей `Escape`.
- **Состояние интерфейса в URL.** В query-параметрах сохраняются поисковый запрос (`search`), статус (`status`), сортировка (`sort`) и идентификатор открытого запуска (`run`). Прямую ссылку можно открыть отдельно или отправить другому человеку.
- **История браузера.** При переходе назад и вперёд приложение восстанавливает состояние фильтров и выбранного запуска из URL.
- **Состояния загрузки и ошибок.** Во время получения данных отображается skeleton. При ошибке появляется сообщение с возможностью повторить запрос.
- **Пустой результат.** Если по текущему запросу и фильтрам ничего не найдено, отображается empty state с возможностью сбросить поиск и фильтры.

## Примеры URL

Состояние страницы можно передавать через query-параметры:

```text
/runs?status=running
/runs?status=failed&sort=duration-desc
/runs?search=api-service&status=failed&sort=oldest
/runs?status=failed&run=run-1040
```

Поддерживаемые значения `sort`:

- `newest` — сначала новые запуски;
- `oldest` — сначала старые запуски;
- `duration-asc` — сначала короткие запуски;
- `duration-desc` — сначала длинные запуски.

По умолчанию используется сортировка `newest`; значение по умолчанию не добавляется в URL.

## Локальный запуск

Требуются Node.js и npm.

Установить зависимости:

```bash
npm install
```

Запустить приложение в режиме разработки:

```bash
npm run dev
```

Собрать production-версию:

```bash
npm run build
```

Локально просмотреть production-сборку после выполнения build:

```bash
npm run preview
```

## Тестирование

Автоматические тесты проверяют:

- фильтрацию по статусу и поиск по названию или репозиторию;
- совместное применение поиска и фильтров;
- сортировку по дате и продолжительности, включая запуски без указанной продолжительности;
- форматирование даты и продолжительности;
- получение mock-данных, имитацию ошибки и повторную загрузку;
- отображение статусов;
- skeleton, error state и empty state;
- открытие и закрытие панели подробностей;
- отображение логов и результата;
- синхронизацию состояния страницы с URL и историей браузера.

## Демонстрация ошибки загрузки

Чтобы увидеть состояние ошибки, откройте:

<https://runforge-henna.vercel.app/?demoError=1>

В этом режиме первый запрос к сервису завершается демонстрационной ошибкой. Интерфейс показывает error state. Нажмите **Try again**, чтобы повторить запрос и проверить восстановление списка.

## Деплой

Приложение опубликовано на Vercel: <https://runforge-henna.vercel.app/>.

После подключения GitHub-репозитория Vercel автоматически запускает новый деплой при отправке изменений в production-ветку, выбранную в настройках проекта. Для frontend-маршрута `/runs` настроен rewrite на `index.html`, поэтому страницу можно открывать напрямую и обновлять без ошибки 404.

## Ограничения

В текущей версии используются демонстрационные данные. Сервисный слой имитирует получение данных с задержкой; реальный backend и интеграция с системой выполнения запусков отсутствуют.

Запуски фактически не выполняются. Отображаемые сведения, логи и результаты являются mock-данными и используются для демонстрации интерфейса, фильтрации, сортировки и обработки состояний.
