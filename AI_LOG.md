## Запросы и переданный контекст

### 1. Подготовка промпта для разработки хука или компонента

**Запрос:**

«Я работаю над проектом RunForge и хочу реализовать новую функциональность, для которой потребуется React-хук или отдельный компонент. Помоги мне сначала правильно составить подробный технический промпт для AI-разработчика.

Не ограничивайся формулировкой задачи в одну-две строки. Нужно описать назначение будущей сущности, её ответственность, ожидаемое поведение, входные параметры, взаимодействие с остальными частями приложения и возможные граничные случаи.

Перед составлением промпта учитывай, что проект уже существует. Необходимо ориентироваться на его текущую архитектуру, изучить используемые типы, компоненты, хуки и принятые соглашения по организации кода. Не предлагай переписывать существующую функциональность или добавлять зависимости без необходимости.

Подготовь промпт так, чтобы по нему можно было реализовать функциональность без неоднозначностей. Включи функциональные и технические требования, ограничения, требования к типизации и критерии проверки результата».

**Контекст:** RunForge — frontend-приложение для просмотра запусков и анализа результатов. Стек: React, TypeScript, Vite, CSS Modules и Lucide React. В проекте уже есть разделение на страницы, компоненты, хуки, сервисы и типы. Используются mock-данные.

### 2. Разработка хука `useRunsUrlState`

**Запрос:**

«Изучи существующую структуру проекта RunForge и реализуй хук `useRunsUrlState`, который будет отвечать за синхронизацию состояния страницы со строкой запроса URL.

Мне необходимо сохранять в URL поисковый запрос, выбранный статус запуска, параметр сортировки и ID выбранного запуска. Это позволит пользователю обновлять страницу, копировать ссылку и возвращаться к нужному состоянию интерфейса.

Реализуй следующие сценарии:

1. При первой загрузке страницы хук должен считывать параметры из URL и устанавливать соответствующее состояние.
2. При изменении поискового запроса, фильтра или сортировки URL должен обновляться.
3. При открытии и закрытии панели с подробностями запуска должен обновляться параметр выбранного запуска.
4. При использовании браузерных кнопок Back и Forward приложение должно восстанавливать состояние из соответствующего URL.
5. Некорректные и отсутствующие параметры должны обрабатываться безопасно с использованием значений по умолчанию.
6. Необходимо избежать бесконечных циклов обновления состояния и URL, а также лишних записей в историю браузера.

Используй React Hooks, TypeScript и стандартные браузерные API. Не подключай дополнительные библиотеки.

Сначала проанализируй существующие типы и реализацию страницы Runs. Определи, какие данные уже хранятся в состоянии страницы, чтобы не создавать дублирующую логику. Затем предложи API хука, реализуй его и покажи полное содержимое изменённых файлов. Объясни, как подключить хук к странице и как проверить его работу».

**Контекст:** Передала структуру проекта, интерфейс `Run`, существующую страницу Runs, параметры поиска, фильтрации и сортировки. Отдельно указала на необходимость поддержки перезагрузки страницы и навигации Back/Forward.

### 3. Разработка компонента `RunDetailsDrawer` и его стилей

**Запрос:**

«Разработай компонент `RunDetailsDrawer` для RunForge. Это боковая панель, которая открывается при выборе запуска из списка и отображает подробную информацию о нём.

Компонент должен получать выбранный запуск через props и не должен самостоятельно загружать данные или дублировать логику страницы.

Необходимо отобразить:

- название запуска;
- текущий статус;
- репозиторий;
- ветку;
- дату и время запуска;
- продолжительность выполнения.

Используй существующий интерфейс `Run`, не придумывай дополнительные поля. Для отображения статуса переиспользуй `StatusBadge`, а для форматирования значений — существующие утилиты проекта, если они подходят.

Предусмотри закрытие панели, корректное поведение при отсутствии выбранного запуска, понятную структуру информации и адаптивное отображение на небольших экранах.

Технические требования:

- React и TypeScript;
- стили в отдельном CSS Module;
- иконки из Lucide React;
- без inline-стилей и сторонних UI-библиотек;
- переиспользование существующих типов и компонентов;
- отсутствие ненужных изменений в других частях проекта.

Сначала изучи существующую реализацию страницы Runs, тип `Run`, `StatusBadge` и утилиты форматирования. Затем предложи структуру компонента и его props. После согласования подхода предоставь полное содержимое файла компонента и CSS Module, а также покажи, как подключить панель к странице».

**Контекст:** Передала интерфейс `Run`, реализацию страницы Runs, существующий `StatusBadge`, утилиты форматирования, текущую структуру компонентов и требования к визуальному стилю проекта.

## Ошибка AI и её исправление

При работе над синхронизацией URL один из предложенных AI вариантов не учитывал полноценное восстановление состояния при навигации браузера с помощью кнопок Back и Forward.

Я заметила проблему во время ручной проверки: после перехода назад URL изменялся, но состояние интерфейса не всегда соответствовало ему. В результате я пересмотрела реализацию хука `useRunsUrlState` и добавила обработчик события `popstate`, который считывает параметры из URL и восстанавливает состояние поиска, фильтрации, сортировки и выбранного запуска.
